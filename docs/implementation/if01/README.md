# IF01 — 正式候选共享语义接口
S01、G01、DB01三个当前收据已满足。共同接口作为K/H/P/F/A/E的候选编写合同，不是G04最终冻结，不增加重复专业主责，也不直接启动学习者运行时。
- interface-contract.json：20种共享对象；DB01全部39类记录的90个typed reference字段路径均有显式目标类型，关系端点另按12种初始类型矩阵；27视图及108要求、原主题引用和实际任务前置；专业主责及状态/权限/观测/策略/流程/组合/评价的边界。KnowledgeRef采用带package/version/kind/stable_id/owner的引用，不是独立重复知识记录。
- interface-fixtures.json：原创新建有限合成夹具，4个逻辑包、两个独立学科上下文。共享类型不意味着学科构念或同类型观测可互换；具体版本、构念、角色、条件和独立性必须匹配。夹具内部manifest用于有限静态见证，绑定合成记录及依赖digest，不替代DB02实际文本文件manifest。
- verify_interface.py：严格schema、完整引用字段路径覆盖、直接依赖及精确身份、稳定ID唯一、入口/终点/优先级、无条件UNKNOWN/STOP/PAUSE/预算耗尽终点、评价对照身份及两上下文绑定。实际40记录、107引用、22种实际夹具记录，17负例拒绝。仅验证声明式合同；并行join字段和成员检查不证明运行时并行或恢复语义。无实际用户、授权、教育效果、专业资格、CQ/LC或持久SQLite。
- 正式模块必须绑定S01/G01/IF01及DAG规定的其他候选输入收据，逐主题D4充分性、来源、反例、案例、验证和明确HOLD独立处理；没有根据旧候选数量自动完成模块。新专业字段/关系类型要明确版本及影响范围，变化触发原合同失效规则。F定义先于P实际组合；具体F/A/E实例依实际专业候选完成，禁止反向重复主责。
